# End-to-end UI + API + DB test

## Solution overview

The automated test **`ExamTest`** walks through the full scenario: it requests a token via the API, authenticates on the UI stand and passes the token as a cookie, compares the project's test table with the data from the DB, creates a project through the interface and a test — directly in the DB (together with a log and a screenshot), after which it verifies the page of the created test.

The solution has three layers working inside a single test:

| Layer | What it does | Implementation |
|---|---|---|
| API | requests a token by the variant number | Rest Assured (`TokenGetClient` → `POST /token/get?variant=`) |
| UI | works with the projects page, the project page and the test page, cookies and a JS method | Aquality Selenium (Page Object + Form) |
| DB | reads the list of tests of the project, creates a test, a log and an attachment | JPA/Hibernate through repositories (`Repository<T>`) |

### Test case and implementation

| Step | Expected result | Implementation in `ExamTest` |
|---|---|---|
| 1. Request a token via the API according to the variant number | Token is generated | `tokenGetClient.getToken(...)` → `POST {baseUrl}/token/get?variant={variant}`, assertion `isNotBlank()` |
| 2. Go to the site. Pass the required authentication. Pass the token generated in step 1 as a cookie (the `token` parameter). Refresh the page | The projects page is open. After the page refresh the footer shows the correct variant number | HTTP Basic Auth (`addBasicAuthentication`) → `CookieManager.save(...)` with the `token` cookie → `goTo` → `CookieManager.load()` → `TabUtil.refreshTab()` → `FooterForm.isVersionEqual(variant)` |
| 3. Go to the page of the project Nexage. Request the list of tests of the project from the DB | The tests of the first page are sorted by date descending and match the result of the DB query | `HomePage.clickProjectBy(...)` → `TestModelRepository.getAllByProjectSortedByStartTime(projectId, DESC)` → comparison of the names, methods and start times of the table rows with the DB |
| 4. Go back to the previous page in the browser (the projects page). Click `+Add`. Enter the project name and save. Close the alert. To close the add-project window call the js method `closePopUp()`. Refresh the page | A success alert appeared. After the method call the add-project window closed. After the page refresh the project appeared in the list | `navigate().back()` → `AddProjectForm.enterProjectName/clickSave` → `waitForSuccessAlert()` → `closePopUp()` (JS from `resources/js/closePopUp.js`) → `refreshTab()` → check of the projects list |
| 5. Go to the page of the created project. Add a test through the DB (together with a log and a screenshot of the current page) | The test appeared without a page refresh | `TestModelRepository.create(...)`, `LogRepository.create(...)` (content — `logs/test.log`), `AttachmentRepository.create(...)` (PNG screenshot of the page) → `TestTableForm.waitForNewLastRow(...)` |
| 6. Go to the page of the created test | All fields hold the correct values. The screenshot matches the one sent | `TestPage.getData()` and `TestPage.getScreenshot()` are compared with the saved test model and the screenshot sent |

### How it works

- **Aquality Selenium as the corporate environment** — the browser, elements and waits are obtained through `AqualityServices`; the environment and test data configuration is read from JSON resources; logs are written to the console and to `logs/test.log`;
- **Page Object + Form** — the pages (`HomePage`, `ProjectPage`, `TestPage`) and the forms (`FooterForm`, `AddProjectForm`, `TestTableForm`) extend `Form`; the locators are moved into `private static final By`, and element names are passed to the factory;
- **Cookie and authentication** — `CookieManager` saves a set of cookies and transfers them into the browser after the site is opened, `Browser.network().addBasicAuthentication(...)` handles HTTP Basic Auth; the host for Basic Auth is derived from `baseUrl` via `URI.getHost()` and is never set manually;
- **The `closePopUp()` JS method** — called through `JsUtil` from the file `resources/js/closePopUp.js` (`jQuery(...).modal('hide')` with a fallback cleanup of the markup); the path to the script is described by the `TestJs` enum rather than by a string at the call site;
- **DB work without "raw" SQL** — HQL templates live in `resources/hql/`, substitutions and named parameters are assembled by the `HqlQuery` builder, and the repositories (`Repository<T>`) encapsulate the session, the transaction and saving; the test calls repository methods only;
- **ORM models** — `TestModel`, `Project`, `Status`, `Author`, `SessionModel`, `Log`, `Attachment`; the meta-model classes (`TestModel_`, `Project_`, ...) are generated by `hibernate-jpamodelgen`, so field names are not duplicated as strings;
- **DTO separation** — the "raw" data from JSON (`ApiTestData`, `DbTestData`, `UiTestData`) and the domain models of the page data (`TestPageData`, `TestTableData`) are separated; `DbEnvironmentData` assembles the JDBC URL from `.env` itself;
- **Type-safe literals** — enums are used instead of strings at the call site: `Endpoint`, `CookieName`, `Attribute`, `TestJs`, `TestPageField`, `TestTableColumn`, `TestStatus`, `SortType`, `AttachmentContentType`, `TestArtifact`, `DbDotEnvKey`, `UiDotEnvKey`;

### Environment

- OS: Windows 10/11 (the instructions assume `cmd`)
- JDK: **Java 25** (Eclipse Temurin)
- Maven: **3.9.16**
- Docker (**Docker Desktop** + **Docker Compose**) — the stand and the DB are brought up as containers from [docker-kits](https://github.com/tquality-education-exam/docker-kits)
- DB: **MySQL 5.7** in a container (schema `union_reporting`, user `login`)
- Stand: the **union_reporting** application (Tomcat in a container), UI — `http://localhost:8080/web`, API — `http://localhost:8080/api`
- Browser: **Google Chrome** (the default profile) or **Mozilla Firefox** — the authentication method on the stand is chosen per browser: CDP for Chrome/Edge, WebDriver BiDi for Firefox
- IDE (optional): IntelliJ IDEA

## How to run

> All commands are executed in **cmd**. After installing Java/Maven, restart the cmd window so that `PATH` is refreshed.

### Step 1. Install Java 25 (Eclipse Temurin)

If it is not installed yet. `winget` is available right in cmd:

```bat
winget install --id EclipseAdoptium.Temurin.25.JDK --source winget --accept-package-agreements
```

Restart cmd and verify the installation:

```bat
java -version
```

### Step 2. Install Maven 3.9.16

**Option A — automatic installation with a single command (from cmd):**

```bat
powershell -Command "$url='https://dlcdn.apache.org/maven/maven-3/3.9.16/binaries/apache-maven-3.9.16-bin.zip'; $dir='%USERPROFILE%\maven'; New-Item -ItemType Directory -Force -Path $dir | Out-Null; $zip=Join-Path $dir 'maven.zip'; Invoke-WebRequest -Uri $url -OutFile $zip; Expand-Archive -Path $zip -DestinationPath $dir -Force; Remove-Item $zip; $mvn=Join-Path $dir 'apache-maven-3.9.16'; [Environment]::SetEnvironmentVariable('MAVEN_HOME', $mvn, 'User'); $path=[Environment]::GetEnvironmentVariable('Path', 'User'); if ($path -notlike '*'+$mvn+'\bin*') { [Environment]::SetEnvironmentVariable('Path', $path+';'+$mvn+'\bin', 'User') }"
```

**Option B — manual installation:**

1. Download the archive manually: <https://dlcdn.apache.org/maven/maven-3/3.9.16/binaries/apache-maven-3.9.16-bin.zip>
2. Unpack it into `%USERPROFILE%\maven` (for example, `C:\Users\<user name>\maven`; create this folder if it does not exist).
3. In cmd run:

   ```bat
   setx MAVEN_HOME "%USERPROFILE%\maven\apache-maven-3.9.16"
   setx Path "%Path%;%USERPROFILE%\maven\apache-maven-3.9.16\bin"
   ```

4. Restart cmd and verify:

   ```bat
   mvn -version
   ```

### Step 3. Install a browser

Download and install one of the supported browsers:

- **Google Chrome**: <https://www.google.com/chrome/>
- **Mozilla Firefox**: <https://www.firefox.com/thanks/>

The driver is downloaded automatically through Selenium Manager.

### Step 4. Install Docker and Docker Compose

The application under test (UI, API and MySQL) is deployed in containers with the ready-made
[docker-kits](https://github.com/tquality-education-exam/docker-kits) set — there is no need to install MySQL and Tomcat locally.

1. Install **Docker Desktop**: <https://docs.docker.com/desktop/install/windows-install/>
   (the Linux option: <https://docs.docker.com/engine/install/ubuntu/>).
2. **Docker Compose** ships with Docker Desktop. Verify that the commands are available:

   ```bat
   docker --version
   docker-compose --version
   ```

   > **P.S.** If Docker Desktop causes problems on Windows, a virtual machine with **Ubuntu Desktop** is more convenient
   > ([installing Docker on Linux](https://docs.docker.com/engine/install/ubuntu/)).

### Step 5. Deploy the stand from docker-kits

1. Get access to the repository with the application sources
   [task-sources](https://github.com/tquality-education-exam/task-sources) — if you have no access, request it from the reviewer.

2. Clone the container set:

   ```bat
   cd /d <path where the stand will be deployed>
   git clone https://github.com/tquality-education-exam/docker-kits.git
   cd docker-kits
   ```

3. In `docker-compose.yml` specify your GitHub login and password (or a personal access token) in the build arguments
   `GIT_USR` and `GIT_PWD` — the container uses them to clone `task-sources` and build the `.war` files.

4. Bring the containers up from the root of `docker-kits`:

   ```bat
   docker-compose up -d
   ```

   The first launch takes a few minutes: the Maven/Tomcat/MySQL images are downloaded and the application is built.
   In recent Docker Compose versions the command is called without a hyphen — `docker compose up -d`; use the variant that is installed.

5. Verify that the stand is up:

   - `http://localhost:8080/web` — the web part (protected by HTTP Basic Auth);
   - `http://localhost:8080/api` — the API;
   - `localhost:3306` — MySQL, schema `union_reporting`.

   The ports are forwarded to `127.0.0.1`, so the stand is reachable only from the machine where Docker is running. If the stand is deployed
   on another host or port, change `baseUrl` in `src/main/resources/ui/environment.json` and
   `src/main/resources/api/environment.json` (the host for Basic Auth is derived from `baseUrl` automatically).

6. On the first start the schema `union_reporting` is created from `dump.sql`. You can check the tables like this:

   ```bat
   docker-compose exec db mysql -u login -ppassword -e "USE union_reporting; SHOW TABLES; SELECT COUNT(*) FROM test;"
   ```

   Expected tables: `test`, `project`, `author`, `status`, `session`, `api_key`, `attachment`, `log`, `variant` and others.
   The `status` table must contain the values `PASSED`, `FAILED`, `SKIPPED`.

### Step 6. Fill in `.env`

Copy `.env.example` to `.env` and specify your values:

```bat
copy .env.example .env
```

The values match the container settings from `docker-kits`: the DB can be accessed as `root` / `root` (`MYSQL_ROOT_PASSWORD`) or as `login` / `password` (`MYSQL_USER` / `MYSQL_PASSWORD`), while `USER_LOGIN` / `USER_PASSWORD` are `TOMCAT_USER` / `TOMCAT_PASSWORD` for the Basic Auth of the UI stand.

```properties
# MySQL connection
DB_HOST=localhost
DB_PORT=3306
DB_SCHEMA=union_reporting
DB_USER=
DB_PASSWORD=
DB_PARAMS=
DB_DRIVER=com.mysql.cj.jdbc.Driver

# Hibernate behaviour
DB_SHOW_SQL=true
DB_FORMAT_SQL=true

# Web Auth
USER_LOGIN=
USER_PASSWORD=
```

If you changed `MYSQL_ROOT_PASSWORD`, `MYSQL_USER`, `MYSQL_PASSWORD`, `TOMCAT_USER` or `TOMCAT_PASSWORD` in the `docker-compose.yml` / `Dockerfile` of the `docker-kits` set — specify your values here.

### Step 7. Run the test

```bat
cd /d <path to the repository>
mvn clean test
```

A single test is started — `ExamTest.shouldCreateTestWithLogAndScreenshot()`. A browser window will open — do not close it manually while the test is running.

**Running in Firefox:**

```bat
mvn clean test -Dprofile=firefox
```

Authentication on the stand works differently depending on the browser (this is encapsulated by `BasicAuthUtil`):

- **Chrome / Edge** — Chrome DevTools Protocol: `Browser.network().addBasicAuthentication(...)`;
- **Firefox** — WebDriver BiDi: interception of the `authRequired` phase and `network.continueWithAuth` with the login and password. For this, `settings.firefox.json` has `webSocketUrl: true` enabled in `driverSettings.firefox.capabilities` — without it BiDi is not enabled and the utility fails with an explicit message.

**Logs** are written to `logs/test.log` and duplicated to the console. The file is overwritten on every run, and its content ends up in the DB as the log of the created test.

### Running through IntelliJ IDEA

1. Install Java 25 through winget (see Step 1).
2. Open the project: **File → Open** and select the repository root.
3. Wait for the dependencies to load and click **Load Maven** in the proposed window.
4. Select the JDK: **File → Project Structure → Project Settings → Project → SDK** — **25 Eclipse Temurin**.
5. Run `ExamTest` (`src/test/java/ru/kaelth4s/tests/test/`) → right-click → **Run**.

## Configuration

### `.env`

The file is created by copying `.env.example` and is not committed to git. The keys are read by `DotEnvManager` (java-dotenv, with a fallback to environment variables and the default values from the `DbDotEnvKey` and `UiDotEnvKey` enums).

### `ui/environment.json`

The address of the UI stand; the host for HTTP Basic Auth is taken from it as well:

```json
{
  "baseUrl": "http://localhost:8080/web"
}
```

### `api/environment.json`

The address of the API stand:

```json
{
  "baseUrl": "http://localhost:8080/api"
}
```

### `api/test-data.json`

The variant number by which the token is requested (it must also be displayed in the site footer):

```json
{
  "postTokenGetRequest": {
    "variant": "1"
  }
}
```

### `ui/test-data.json`

Project names: the existing project for step 3 and the name of the project created in step 4:

```json
{
  "projectName": "Nexage",
  "newProjectName": "test11"
}
```

### `db/test-data.json`

The data of the test being created: the name (a run timestamp is appended to it), the fully qualified name of the test method and the environment:

```json
{
  "test": {
    "name": "auto_test_",
    "methodName": "ru.kaelth4s.tests.test.ExamTest.shouldCreateTestWithLogAndScreenshot",
    "env": "local"
  }
}
```

### `settings.json` / `settings.firefox.json`

Aquality settings: browser, timeouts, log language, cookie behaviour. `settings.json` is the default profile (Chrome), `settings.firefox.json` is enabled by the `-Dprofile=firefox` key. In the firefox profile `webSocketUrl` is enabled in `capabilities` — it is required for BiDi authentication.

### `log4j2.properties`

A single log format for the console and the `logs/test.log` file:

```properties
appender.console.type=Console
appender.console.name=ConsoleAppender
appender.console.layout.type=PatternLayout
appender.console.layout.pattern=%d{yyyy-MM-dd HH:mm:ss} %-5level - %msg%n
appender.file.type=File
appender.file.name=FileAppender
appender.file.fileName=logs/test.log
appender.file.append=false
appender.file.layout.type=PatternLayout
appender.file.layout.pattern=%d{yyyy-MM-dd HH:mm:ss} %-5level - %msg%n
rootLogger.level=info
rootLogger.appenderRef.console.ref=ConsoleAppender
rootLogger.appenderRef.file.ref=FileAppender
```
